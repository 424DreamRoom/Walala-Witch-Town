哗啦啦魔女镇：十万字剧情对白内容包
编写日期：2026-10-11

本目录是独立剧情稿和结构化对白内容包。尚未接入现有游戏运行、NPC地图、好感、存档和四语言UI。
主角、原有十一名角色、十二章主线和结局沿用 Scenes/Campaign 的现有设定。
新增居民属于本稿新增设定；他们的职业场所、个人事件和出场条件是叙事设计，不能据此认定游戏已实现相关建筑或系统。

最终生成文件：
剧情对白全集.txt：按主线、居民组和人物排序的完整可读稿。
人物与事件索引.txt：人物声线、关系、场景及事件前置条件。
dialogue_bundle.json：合并后的完整结构化对白，适合后续编辑和接入。
validation_report.json：实际汉字数、对白条数、场景数、人物覆盖和一致性核验。
创作依据与参考.txt：已检索的教学与游戏参考、可借鉴的结构和本稿采用的具体写法。

统计口径：只计算场景 lines[].text 中的正文汉字；标点、空格、说话人字段、标题、人物设定、触发条件、资料笔记不计入十万字。重复的整条正文不重复计数。另列对白和动作描写汉字数，避免用人物册或技术字段补足对白篇幅。

scene.requires 为编辑用的前置事件ID，并非游戏已实现的触发器；chapter_min 沿用现有零基章节编号（0对应第一章）。个人支线采用独立事件顺序，不要求玩家在某一天内完成。
新增地点使用“地点设计”处理，接入时可映射到已有小镇、农场、食堂、码头、森林、石谷、湿地、旧械遗址、霜铃山径、月环观星台。对白不会出现操作教学。

构建与检查：在项目目录执行 python Narrative/Longform_20261011/assemble.py 。程序只写本目录的合并稿、索引和报告，不扫描清理任何目录，不写MyArt、不读写玩家进度。

正文源稿：mainline_source.txt、core_residents_build.py、town_residents_build.py、valley_residents_partNN.py均保存逐场手写原文。构建器只解析与组织这些原文，没有句子组合扩写或程序填充对白。
修改居民原文后，先分别运行 core_residents_build.py、town_residents_build.py、valley_residents_build.py，再运行 assemble.py；主线由assemble.py自动解析。
修改结构化JSON后直接运行assemble.py可以汇总，随后重新运行居民builder会恢复该组源稿内容，因此长期编辑应以原文源稿为准。
最终要求正文和纯对白去重汉字数都达到100000；标点、说话人、附录和重复整句不计数。通过后自动生成剧情内容包.zip。
