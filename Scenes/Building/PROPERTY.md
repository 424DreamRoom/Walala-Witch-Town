# 房地产魔女与房屋占地

绮屋白天位于小镇餐厅西侧，地图有「房地产魔女」标记。世界角色复用现有粉帽深蓝长发魔女的原生 32×32 待机帧，不修改任何角色素材。走到她身边后使用现有世界互动即可打开服务窗口；窗口内可承租餐厅或查看住宅扩建。原家具店仍保留扩建服务。操作说明仅写在本文，玩家界面只显示名称、价格、条件、状态和结果。

餐厅长期租约一次支付 60 金币，没有周期扣租或到期回收。新游戏尚未承租，餐厅入口与营业受真实租约状态限制；白天结束时，未承租的玩家仍留在当前场景，可以继续采集和交易。已有存档缺少租约字段时保留餐厅使用权，包括正在营业的存档。租金不足、已经承租、夜间和过期窗口回调都不会重复扣费。

新游戏扩建时同时增加室内地板、室外建筑外观和真实碰撞占地。单位为 16 原生像素：

| 等级 | 室内地板 | 室外地基 | 本级费用 |
| --- | --- | --- | --- |
| 小空屋 | 12×8 | 10×6 | 初始 |
| 舒适小屋 | 20×13 | 13×7 | 120 金币、30 木材、3 铁锭 |
| 宽敞之家 | 32×18 | 16×8 | 400 金币、80 木材、8 铁锭 |

门口、返程落点和原有室内家具不移动。扩建前检查新增地基内的作物、施肥土地、农场建造物和未采完的自然资源；用地被占用时禁用购买并显示原因，不移除物品、不扣费。未种植、未施肥的空土可以并入新地基，避免采收后的空土永久锁住扩建。种植、家具摆放、出口寻路、屋顶遮雨和地图显示共享扩建后的几何。

原有存档加载时不自动扩大室外占地，避免覆盖玩家的农场布置。室外等级落后于室内时，扩建优先补上一级室外占地，按对应地基等级收费，原有室内等级和家具保持不变。因此原本已达到最大室内面积的旧房屋也能购买两次新的占地扩建。旧存档中的固定家具继续保留。

`house_catalog.gd` 统一升级方案、室内外尺寸和价格。扩建外观在内存中复用现有房屋的原生砖瓦与木墙片段拼接侧翼，中央房屋、门窗保持原有像素；源文件不写入、不调色、不缩放。`exterior_level` 与 `restaurant_leased` 属于各自独立存档，正常沿用六小时、手动及退出保存机制。

## 验证

```powershell
python Localization/build_catalog.py
python Scenes/Building/run_property_verification.py headless
python Scenes/Building/run_property_verification.py capture
python Scenes/Building/run_property_verification.py housing
python Scenes/Building/run_property_verification.py restaurant
```

运行器为每个进程隔离 APPDATA、LOCALAPPDATA、测试设置和存档，限制运行时长，并在运行前后核对 `MyArt/` 的全部文件 SHA-256。日志与四语言窗口、NPC、地图及扩建实机截图位于 `output/property_service/`。专项覆盖精确扣费、无租约禁止营业、自然资源/作物/家具占地保护、实际扩建碰撞、门口可达、原有箱内物品、旧存档补充占地、非法存档、夜间与过期服务、世界销毁后的磁盘回读。

全局语言回归脚本 `Localization/verify_localization.gd` 仍引用已移除的 `hud.Journal` 接口，在该处中止；本次新增服务的四语言切换、文本宽度和实机截图由 `verify_property.gd` 独立覆盖，词库构建同时检查全部源文案与翻译覆盖。

最终专项功能断言 76 项、房屋回归 48 项、餐厅回归 54 项通过。并行新增钢琴期间，后一次运行的整体退出码还受到钢琴采样尚未导入、钢琴翻译尚未添加的影响；运行器保留原始错误并返回失败，未将这些错误过滤为成功。较早的同功能运行已有无相关加载错误的 75 项专项及 48 项房屋回归记录。详见 `output/property_service/validation_summary.json`。
